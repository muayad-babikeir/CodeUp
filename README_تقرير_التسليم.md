# CodeUp — تقرير التسليم

## ⚠️ الأهم أولًا: ما لم يتم فعليًا
لا توجد شبكة إنترنت في بيئة العمل التي كتبت فيها هذا الكود، لذلك **لم أتصل بمشروع Supabase الفعلي، ولم أُشغّل الـMigration حيًا، ولم أختبر RLS أو أي تدفق (Join Request, Leader Application, رفع ملف...) على بيانات حقيقية.**
كل ما فعلته هو:
- كتابة الكود كاملًا حسب المواصفة.
- فحص بنيوي offline: `node --check` على كل ملفات JS (نجح الكل)، وفحص توازن الأقواس و`$$` في ملف الـSQL (متوازن).
- مراجعة يدوية للمنطق (صلاحيات، RLS، RPC).

هذا **لا يغني عن اختبارك الفعلي** حسب مصفوفة الاختبار في المواصفة الأصلية (قسم 65) قبل الاعتماد على النظام. تحديدًا اختبر يدويًا:
1. تسجيل حسابين، اجعل أحدهما Super Admin يدويًا (خطوة أدناه).
2. أنشئ كورس + مجموعتين، وتأكد Squad A Leader لا يرى بيانات Squad B (المفروض تفشل الاستعلامات بصمت لأن RLS تُرجع صفوفًا فارغة، لا خطأ).
3. جرّب Approve/Reject على Join Request من مستخدم لا يملك صلاحية — يجب أن يفشل الـRPC برسالة عربية واضحة.
4. جرّب رفع ملف تسليم وتأكد أن رابط التحميل الموقّع (Signed URL) يعمل فقط لصاحبه أو أدمن/قائد الكورس.

## الخطوات للتشغيل
1. **شغّل الـSchema الأصلي أولًا** (`codeup-schema.sql` الذي رفعته) إن لم يكن مُشغّلاً على مشروعك بالفعل.
2. افتح **SQL Editor** في Supabase Dashboard، الصق `database/2026_codeup_platform_migration.sql` كاملًا وشغّله. آمن لإعادة التشغيل (idempotent).
3. أنشئ حسابك الأول من صفحة `index.html`، ثم في SQL Editor:
   ```sql
   update profiles set is_super_admin = true where email = 'your-email@example.com';
   ```
4. ارفع الملفات على الاستضافة بنفس البنية:
   ```
   index.html              ← تطبيق الطالب
   codeup-logo.svg         ← شعار placeholder (استبدله بشعارك)
   js/supabase.js          ← عميل Supabase المشترك
   js/shared.js            ← دوال مشتركة (Toast, RPC wrappers, Role resolution...)
   admin/index.html        ← لوحة الإدارة (منفصلة تمامًا عن تطبيق الطالب)
   admin/css/admin.css
   admin/js/app.js         ← Auth guard + توجيه حسب الدور (Super/Course Admin/Leader)
   admin/js/dashboard.js
   admin/js/courses.js     ← الكورسات، أدمن الكورسات، إعدادات الكورس، التقدم
   admin/js/people.js      ← المستخدمون، المجموعات، القادة
   admin/js/requests.js    ← طلبات الانضمام وطلبات القيادة (قبول/رفض عبر RPC)
   admin/js/work.js        ← الواجبات والتسليمات (مراجعة وتقييم)
   admin/js/community.js   ← المستجدات (إشراف) والإعلانات
   admin/js/audit.js       ← الملفات، سجل التدقيق، ولوحة القائد الكاملة (My Squad)
   ```
5. **Storage**: تأكد أن الـbuckets الثلاثة (`submissions` خاص، `avatars` و`course-assets` عامان) موجودة — الـschema الأصلي ينشئها. الـmigration يضيف سياسة قراءة إضافية لأدمن/قائد الكورس على bucket التسليمات.

## ما الذي أضافه الـMigration (فوق الـschema الأصلي دون حذف أي شيء)
**5 جداول جديدة:** `squad_join_requests`, `leader_applications`, `comments`, `reactions`, `notifications`
**أعمدة جديدة:** `assignments.squad_id/type/created_by`, `submissions.content/visibility`, `squads.capacity/description/status`, `courses.status`, `file_uploads.submission_id/file_size`
**14 دالة/RPC:** بما فيها 4 دوال ذرية (Atomic) لعمليات القبول/الرفض تحدث كلها داخل معاملة واحدة (تحقق صلاحية → تحقق سعة → إنشاء العضوية → تحديث الطلب → تسجيل النشاط → إشعار) — إما تنجح كاملة أو تفشل كاملة، لا حالة نصف مكتملة.
**RLS كاملة** على كل جدول جديد، وتحديث لسياسة `submissions` لدعم رؤية الـTimeline (خاص/مجموعتي/الكورس كله).
**Trigger** يمنع أي مستخدم من ترقية نفسه لسوبر أدمن حتى لو حاول تعديل صف نفسه في profiles مباشرة.

## قيود معروفة (اخترتها عمدًا لتبسيط النطاق، وليست أخطاء)
- **العضوية في مجموعة** تعيش في `enrollments.squad_id` الموجود أصلًا — لم أنشئ جدول `squad_members` منفصل لتفادي ازدواجية مصدر الحقيقة، بما يتماشى مع تعليمات المواصفة بالحفاظ على البنية الحالية.
- **الـTimeline** هي التسليمات نفسها بحقل `visibility` بدل جدول `timeline_posts` منفصل — نفس منطق تفادي الازدواجية.
- الإشعارات (Notifications) نص/عنوان فقط بدون Push حقيقي (المواصفة قالت "إذا كانت البنية مناسبة" — أضفتها كجدول + إدراج تلقائي من RPCs، بدون قناة توصيل خارجية).
- ملف الشعار `codeup-logo.svg` مجرد placeholder بسيط لأن الملف الأصلي لم يكن ضمن ما رفعته — استبدله بشعارك.
- لوحة الإدارة مبنية بتصميم عملي (جداول + Modals) وليست مصممة بصريًا بعمق كتطبيق الطالب — لو احتجت تصميمًا أغنى بصريًا أقدر أطوّره في جولة لاحقة.

## ماذا تفعل لو وجدت مشكلة عند التشغيل الفعلي
غالبًا ستكون مشاكل تكامل صغيرة (اسم عمود، ترتيب استدعاء) تظهر فقط عند التشغيل الحي — أخبرني بنص الخطأ من Supabase وأنا أصلحه فورًا.
